# Deploying Mê Kitchen to Netlify

This folder is the whole site. No build step, no dependencies to install.

## Auto-deploy is live

This repo (`github.com/NavrenNathan/mekitchen`) is connected to the Netlify
project. **Every `git push` to `master` deploys automatically** — no CLI
command needed. Anyone with push access to the repo can ship a change just
by pushing.

```
deploy/
├── index.html      coming-soon holding page — what me-kitchen.com serves (noindex)
├── home.html       the main site, /home, behind the holding page's gate
├── menu.html       full menu, /menu — matches the Square ordering site, with Menu structured data
├── story.html      the Our story page, /story
├── careers.html    careers page with the "careers" Netlify application form, /careers
├── privacy.html    privacy policy, /privacy — linked from every footer
├── 404.html        not-found page (Netlify picks this up automatically; noindex)
├── llms.txt        plain-text summary of the site for AI tools
├── robots.txt      currently blocking search engines — see below
├── sitemap.xml     generated by scripts/generate-sitemap.mjs
├── netlify.toml    security headers (incl. CSP), caching, redirects
├── assets/         photos (JPEG + WebP sizes), video, logos, favicons, og-image.png
├── assets/js/      page scripts (see "Editing scripts" below)
├── fonts/          self-hosted Space Grotesk and Geist (+ OFL licences)
├── scripts/        checks and generators (blocked from public download)
└── docs/           website-checklist.md and local-listings.md (blocked from public download)
```

`me-kitchen.com` serves the coming-soon holding page. The full site sits at
`/home` (`home.html`), reached through the concealed password gate at the
bottom of the holding page — the dim dot under the footer. The password is stored
only as a SHA-256 hash in `index.html`'s inline script (ask Nathan for it);
the comment there explains how to change it.

The site was temporarily flipped (main site at the root) so a Semrush audit
could crawl it, then flipped back. If it is ever flipped again, three things
must move together or the site breaks:
  1. `home.html`'s canonical and `og:url`
  2. the `href="home.html"` links in menu/story/careers/privacy, and the
     breadcrumb "Home" URL and `Restaurant` `url` in the structured data
  3. the `netlify.toml` redirects — a `/home.html -> /` rule while the main
     site lives at `/home` bounces every visitor onto the holding page
Then rerun `node scripts/generate-sitemap.mjs` and the two check scripts.

**Only `index.html` (the holding page) and `404.html` carry a noindex tag.**
The main pages don't; `robots.txt` is what keeps Google out (below).

## Editing scripts, fonts and photos

- **Scripts** live in `assets/js/` (`site.js` and `footer.js` are shared;
  the rest belong to one page each). Pages load them as
  `assets/js/name.js?v=<fingerprint>`. After editing any of them, run
  `node scripts/stamp-assets.mjs` so the fingerprints change and returning
  visitors don't keep a stale copy. `--check` fails if anything is stale.
- **The security policy** (`Content-Security-Policy` in `netlify.toml`)
  allows scripts from this site only, plus the home page's one-line head
  script by its hash. Don't add inline `<script>` blocks or `onclick=`-style
  handlers: they will be blocked. If you edit that head script,
  `stamp-assets.mjs` prints the new hash to paste into `netlify.toml`.
- **Fonts** are in `/fonts/` and cached for a year; replace a font only
  under a new file name.
- **Photos**: each content photo has WebP copies (`name-480.webp` and so
  on). If you replace a photo, regenerate its WebP sizes too, or the old
  ones will keep showing.

## Deploy it

**Push to `master` on GitHub. That's the whole deploy.** The me-kitchen.com
Netlify project (in the client's Netlify account, not ours) builds from the
repo automatically, usually within a minute.

Don't use Netlify Drop or `netlify deploy` from this folder: either one
publishes a *separate* copy of the site to whichever Netlify account you're
logged into, at a different URL, and me-kitchen.com doesn't change.

Before pushing, run:

```bash
node scripts/stamp-assets.mjs --check   # script fingerprints current
node scripts/check-links.mjs            # no broken links
node scripts/check-seo.mjs              # no indexing mistakes
```

## The site is currently hidden from Google — on purpose

`Disallow: /` in `robots.txt` is what keeps search engines out. The holding
page also carries `noindex`, which stays for as long as it is a holding page.

On launch day, delete the `Disallow: /` line from `robots.txt` and redeploy.
The full launch steps, and everything still outstanding, are tracked in
`docs/website-checklist.md`.

## Security note

There is a `netlify-token.txt` sitting on the Desktop in plain text. If that is a
live Netlify access token, anyone with access to that machine — or any backup or
sync of that folder — can deploy to or delete your sites.

Revoke it in Netlify (User settings → Applications → Personal access tokens),
then delete the file. Deploying doesn't need a token at all: it happens by
pushing to GitHub.
